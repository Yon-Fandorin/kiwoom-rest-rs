# SDK 검증 범위와 결과

검증 대상은 `kiwoom-core`, `kiwoom-domain`, `kiwoom-client`입니다. 독립 작성한 응답과 토큰을 사용하는 mock 테스트, `127.0.0.1`의 임시 HTTP·WS 서버로 클라이언트 동작을 확인했습니다. 실제 키움 서버 연결과 실계좌 인증은 검증하지 않았습니다.

## 계약과 HTTP 전송

[계좌](contracts/accounts.md), [시장](contracts/market.md), [차트](contracts/charts.md), [분석 조회](contracts/analytics.md), [상품·환율 조회](contracts/products.md), [주문·예약·환전](contracts/orders.md)의 mock 테스트는 요청 본문, 필수 입력, API-ID, 경로와 응답 필드를 검사합니다. 중첩 배열, 선택 필드 생략, 확인된 빈 배열, 알 수 없는 필드를 구분하며 원본 응답을 보존합니다. 날짜·시간·코드·종목 표기가 문서 조건을 벗어나면 전송 전에 거부합니다. 응답의 금액·수량 문자열과 알 수 없는 값에 금융 의미를 추정해 붙이지 않습니다.

0B 호환 디코더는 REAL 프레임의 실패 코드, 잘못된 코드 형식과 객체가 아닌 데이터 항목을 거부하는지 확인합니다.

공통 계약 테스트는 API-ID 불일치, HTTP 오류, 업무 오류, 잘못된 성공 응답, 반복 커서와 페이지 한도, 연속조회 헤더를 다룹니다. `Retry-After`의 초·세 가지 HTTP 날짜 형식, 소수 초의 올림과 제한된 읽기 재시도도 확인합니다. 헤더 이름의 대소문자, 제어 헤더 중복·잘못된 값, 오류 본문 수신 실패가 상태와 대기 지시를 잃게 만들지 않는지도 검사합니다. 30초를 넘는 서버 대기는 호출자에게 돌려주며 조기 재시도하지 않습니다. 단일 페이지 호출은 성공적으로 디코딩한 typed 페이지와 원본 응답을 반환합니다. 실패하거나 디코딩하지 못한 응답의 본문을 별도 실패 기록으로 반환하는 기능은 없습니다.

금융 변경 요청은 기본 차단합니다. 명시적으로 활성화한 경우에도 HTTP 401·503, 전송 실패와 업무 오류 후 자동 재실행하지 않습니다. 위조한 API-ID·경로와 미등록 경로는 전송 전에 거부합니다. 인증 관리 계층에서는 이런 요청을 토큰 획득 전에도 거부하는지 검사합니다. HTTP/2의 `REFUSED_STREAM` 응답에도 실제 요청 본문이 한 번만 전송되는지 로컬 서버에서 검사합니다. 입력 검증 이전의 기본 거부, 토큰 발급·간격 대기·전송 중 취소와 발급 실패도 확인합니다. Debug와 오류의 민감정보 가림도 테스트합니다.

실제 `reqwest` 전송 테스트는 임시 HTTP 서버에서 POST 경로, JSON 본문, 인증·API-ID·연속조회 헤더와 응답 처리를 확인합니다. `tungstenite` 전송 테스트는 임시 WS 서버에서 연결, 합성 LOGIN 프레임 교환, 미지원 메시지 거부와 종료를 확인합니다. 이 결과에는 증권사 도메인의 네트워크·TLS 호환성 검증이 포함되지 않습니다.

새 레이어의 REST 호출은 `rest::Client`에 전송 포트를 주입하고 `domain` 요청으로 mock 왕복을 확인합니다. WS 호출도 최상위 `ws::Client` 경로로 검증합니다. 역방향 의존·숨긴 네트워크 의존·계약 속 비동기 실행을 거절하는 검사와, 분리된 DTO만으로 typed 호출 지원을 주장하지 못하도록 하는 회귀 검사를 포함합니다.

공개 경로 호환성 테스트는 인증·계좌 거래내역·페이지 타입의 기존 경로와 새 경로가 같은 정의를 가리키는지 확인합니다. 세 미국 가격조회는 공통 검증으로 옮긴 뒤에도 원본 소수 문자열, 정밀도 한계, 시작·종료 필터의 오류 순서와 전송 전 거절을 유지하는지 mock 호출로 검사합니다.

## 토큰과 인증 관리

[토큰 관리](contracts/token-lifecycle.md) 테스트는 호출자가 지정한 만료 시각 해석, 시계 여유 경계, 동시 호출 30건의 발급 1건 공유, 오래된 세대의 무효화 방지와 실패 대기를 확인합니다. 발급 담당 호출 취소, 발급 시간 초과, 짧거나 잘못된 만료값, 잘못된 bearer 형식, 산술 오버플로와 주입한 client-credentials 발급도 다룹니다. HTTP·WS에서 같은 메모리 토큰 관리자를 사용할 수 있습니다.

[인증 관리 전송](contracts/managed-auth.md)은 기본적으로 HTTP 401 이후 갱신·재실행을 하지 않습니다. 호출자가 `SafeReadHttp401Once`를 선택하면 등록된 읽기 요청을 새 토큰으로 한 번 재실행합니다. 반복 401, OAuth 재귀와 임의 업무 오류를 인증 오류로 바꾸는 처리를 거부하는지 검사합니다. 읽기 재시도와 인증 재실행을 함께 사용하면 페이지당 자원 요청 상한은 `2 * (max_read_retries + 1)`입니다.

발급 제한 시간에는 토큰 관리자 잠금 대기가 포함되지 않습니다. 전체 호출 마감시간이 필요하면 호출자가 별도로 적용해야 합니다. [공개 au10001 응답 표](https://openapi.kiwoom.com/guide/apiGuideContents/a1/au10001)는 `expires_dt`의 시간대나 고정 TTL을 명시하지 않습니다. 실제 사용 전에 만료 시간대와 서버 수명을 확인해야 하며, 테스트에서 지정한 오프셋·시계 여유·실패 대기는 로컬 정책입니다.

## WS 세션과 복구

WebSocket 구현은 `ws` 모듈에 모았습니다. 기존 모듈 alias와 새 경로의 타입 동일성, 기존 전송 포트와 조건검색 요청을 새 세션에서 사용하는 mock 왕복도 검사합니다.

[실시간 계약](contracts/realtime.md)은 피드 23개와 피드별로 집계한 FID 항목 575개, [조건검색 계약](contracts/conditions.md)은 서비스 8개를 다룹니다. 테스트는 구독 유형, ID 대소문자, 원본·알 수 없는 필드 보존, LOGIN/PING, 조건검색 순번과 제한된 이벤트 버퍼를 검사합니다. 응답 코드가 없으면 확인되지 않은 상태로 남깁니다. 잘못된 프레임, I/O 실패, 시간 초과나 실행 중인 future 취소 후에는 새 전송 연결이 필요합니다. 네트워크 코덱의 프레임·메시지 크기 한도는 연결 시 설정합니다. 시계에 더할 수 없는 작업·연결 기한은 생성 시 거부합니다. 전송과 PING 응답의 실패·지연, LOGIN·수신·종료 취소, 처음 폴링하기 전 future를 폐기했을 때 인증·I/O 상태 보존, 순번 생략과 공유 잠금을 통한 동시 호출 직렬화도 검사합니다. 코덱 제어 Ping/Pong과 연속 제어 프레임 한도, 바이너리 거부, 연결 종료와 단일 프레임·분할 메시지의 크기 초과는 로컬 서버에서 확인합니다.

[WS 복구](contracts/ws-recovery.md) 테스트는 새 LOGIN 이후 확인된 그룹과 연속 조건검색을 재실행하는 흐름을 다룹니다. 그룹 교체·추가·제거, 미국 종목 객체의 정확한 제거, 국내·미국 조건검색 순번 분리, 조건검색 해제와 새 세대의 초기 스냅샷을 확인합니다. REAL/PING 교차 수신, 앞선 구독 ACK 이후 뒤쪽 그룹·조건검색의 부분 재실행 실패, 잘못되거나 누락된 ACK, 세션 시간 초과, 취소·종료와 이전 연결 폐기도 검사합니다. 토큰 획득, 연결 팩토리, LOGIN, 구독 복구와 대기는 시도 횟수와 하나의 절대 마감시간 안에서 실행됩니다.

구독 설정은 성공 ACK와 typed 디코딩을 확인한 뒤에만 갱신합니다. 응답에 그룹·순번이 없으면 단일 요청 세션에서 서비스 응답을 받았다는 사실까지만 확인할 수 있습니다. 서버가 모든 구독 항목을 정확히 반영했는지는 알 수 없습니다. 재연결에 성공해도 미해결 누락 표시는 남습니다. 누락 표시의 용량에 도달하면 기존 기록을 버리지 않고 추가 I/O를 거부합니다. 복구 상태는 메모리에 있으며, 재접속은 놓친 이벤트를 복원하거나 스트림 연속성을 증명하지 않습니다.

## 응답 필드 검증의 깊이

차트·상품 fixture는 문서 필드별로 다른 합성 값을 사용하고 각 타입의 이름 있는 필드와 원본 JSON을 대조합니다. 실시간 피드 0B·0D·FE의 200개 필드와 조건검색 행의 29개 필드도 개별 이름으로 대조합니다. 나머지 실시간 피드는 전체 FID 집합·순서와 대표 필드, 직렬화 왕복을 검사하며 모든 이름 있는 필드의 의미를 개별 검증한 것은 아닙니다. 분석 조회와 일부 주문·계좌·시장 응답도 대표 필드 검증이므로 모든 필드의 금융 의미를 보장하지 않습니다.

## MCP 앱과 API 유지보수

[조회용 MCP 앱](../apps/kiwoom-mcp/README.md)의 24개 테스트는 도구 5개의 typed SDK 호출, 원본·출처·연속 조회 보존, 설정 프로필의 목록·직접 호출 제한, 입력·페이지·결과·동시 실행·시간 상한을 확인합니다. 실제 실행 파일의 stdio 왕복과 최신 `2026-07-28` 및 이전 `2025-11-25`의 HTTP 요청도 합성 데이터로 검사합니다. HTTP 인증·Host·Origin·중복 제어 헤더·chunked 본문 제한, 이전 세션 생성·재사용·삭제·만료·정리와 프로필 우회 거부를 포함합니다.

취소 통지, 최신 HTTP 연결 종료, 이전 세션 DELETE와 서버 종료 후 대기 중인 SDK 전송이 폐기되고 다음 페이지가 시작되지 않는지 실제 MCP 메시지와 loopback 연결로 검사합니다. 이전 규격의 버전 헤더 생략 요청에도 같은 세션 취소 정책을 적용합니다. controlled-time 세션 테스트는 만료가 조회 취소 신호와 세션 map 정리를 함께 수행하는지 확인합니다. 이것은 브로커가 이미 받은 요청을 되돌리거나 처리 여부를 확정한다는 뜻이 아닙니다.

MCP의 기본 backend는 합성 데모이고 금융 변경·OAuth 발급·WS 실시간 구독 도구는 없습니다. 각 서버는 하나의 계정 토큰·프로필 범위이며 여러 계정의 사용자 인증을 처리하는 공유 서비스가 아닙니다. 외부 MCP 제품과의 실제 접속, 실제 브로커 응답·인증, 여러 인스턴스의 세션 공유와 실시간 MCP는 검증하지 않았습니다. [MCP 계약](contracts/mcp.md).

프로젝트 API 유지보수 도구의 14개 합성 회귀는 공개 메뉴·계약 표 파싱, 부분 수집·parser 변경·출처 무결성 구분과 릴리즈 노트 중복 방지·동일 staged 변경 포함을 검사합니다. 이 결과는 문서 품질 검수, 독립 에이전트의 행동 평가, 실제 API 전체 변경 조사와 별개입니다. 전체 공개 상세 페이지와 표 밖 공지·설명이 최신인지 증명하지 않으며, 첫 스냅샷을 변경 없음의 근거로 쓰지 않습니다. 날짜별 수집·평가 원문은 Git 제외 `local/`에 보관합니다.

## 실제 서버에서 확인할 사항

- 서버의 호출 한도·구독 한도·제한 정책. 요청 간격과 재시도 횟수는 로컬 설정입니다.
- 실제 인증, 토큰 만료 시간대·수명·외부 폐기와 업무 오류 의미.
- 요청 파라미터의 서버 수용, 실제 응답 필드·식별자 범위, 조회 보존 기간과 금융 값의 의미. [현재 ust21100 표](https://openapi.kiwoom.com/m/guide/apiguide/32/ust21100)는 필수 `tp=0/3/4/5`를 명시합니다. 다른 자료에서 관찰한 `tp=8`은 현재 지원으로 확정하지 않았습니다.
- 실시간 ACK의 상관관계, 연결 종료·재구독의 실제 동작과 누락 구간의 확인.
