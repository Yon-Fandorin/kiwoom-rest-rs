# Independently authored chart and sector contracts

These contracts use the unauthenticated public web guide observed on 2026-10-12. No official SDK, CLI, MCP source or schema was copied or transformed. These contracts have local mock evidence; account APIs and real responses remain unvalidated.

Each named method validates required fields, documented lengths and enumerated choices. It checks calendar dates described as YYYYMMDD and uses the shared transport for authenticated reads and pagination. Request fields documented as optional remain optional. Responses retain every documented string field as `Option<String>` and every documented list as an optional vector of concrete row types. They preserve unknown root and row fields in `extra` and retain the complete original JSON and page headers alongside the typed view. Empty strings, signs and padding are preserved. Raw pages distinguish absent fields from null fields; the optional typed view maps both to None.

USD chart `exrt_appl_tp` is a documented selection code. The client infers no conversion semantics, historical FX provenance, ledger trade amounts, taxes or dividend interpretation from it. Adjusted chart prices are not ledger acquisition cost. The seven gold chart methods appear in the chart category of the current domestic public guide. Their inclusion does not imply a separate product service.

The 42 per-API mocks check the exact API identifier, documented route, every request key and every documented response string at the root and row levels. They also check unknown-field preservation, a two-page cursor round trip and raw JSON equality. Synthetic strings include signs, padding and decimal places; they are not quoted broker examples. Additional tests reject invalid required fields, dates, choices and lengths before transport and check optional-field omission and typed handling of empty strings and null values.

## Document inconsistency

The `ka20007` request body documentation lists `inds_cd` length 8 and `base_dt` length 3, but describes the latter as `YYYYMMDD`. The independently authored client requires a valid eight-digit calendar date and leaves the documented length contradiction unresolved. It neither truncates the date nor assumes server behavior. Kiwoom documentation or support must resolve this discrepancy before live compatibility can be claimed. Other length checks follow each endpoint's documentation; the client imposes no US ticker length where the documentation omits it.
